# ふるさと納税計算（furusato-keisan）構想メモ

**作成**: 2026-07-25（社会保険計算セッションにて。Fable5 一次ソース検証＋競合調査に基づく）
**ステータス**: 構想 Draft v1（未着手・ドメイン未取得）
**結論先出し**: **条件付きGO。「国保加入者（自営業・年金受給者）の一気通貫上限計算」を主砲にした参入なら勝ち筋あり。単なる「正確なシミュレータ」では後発で厳しい。**

---

## 1. 考え方（制度の構造）

### 控除の三層構造 [確認済・総務省/国税庁]

ふるさと納税＝寄附額のうち2,000円を除く全額が、次の3つで戻る仕組み。

1. **所得税**（所得控除）: (寄附額−2,000円) × 所得税率 × 1.021（復興税・〜令和19年分）
2. **住民税基本分**（税額控除）: (寄附額−2,000円) × 10%
3. **住民税特例分**: (寄附額−2,000円) × (90% − 所得税率×1.021)
   - **特例分の上限 ＝ 住民税所得割額の20%**（これが「上限額」の正体）

### 自己負担2,000円で済む上限額（逆算式）

```
上限額 = 住民税所得割額 × 20% ÷ (90% − 所得税限界税率 × 1.021) ＋ 2,000円
```

- 式の構成要素はすべて一次ソースで[確認済]。ただし**この逆算式そのものを総務省は公式掲載していない**（境界条件からの数学的導出）[確認済]
- 計算チェーン: 給与収入 → 給与所得 → 所得控除（社保実額・iDeCo・基礎・扶養…）→ 課税所得 → ①所得税限界税率 ②住民税所得割額 → 上限
- **住民税所得割10%はほぼ全国一律**（指定都市の8%/2%配分は合計不変で影響なし）[確認済] → **自治体別ページ展開の必然性は弱い＝47県/1741ページ構成はドアウェイ化リスク。1ツール集中型が正**
- 神奈川県超過課税0.025%が特例分2割上限の算定基礎に入るかは[未確認]（影響は極小と推測。実装前にe-Gov照合）

### ワンストップ特例 [確認済]

- 要件: 確定申告不要の給与所得者等＋寄附先5団体以内（地方税法附則7条）
- **確定申告するとワンストップは無効**（医療費控除等で申告する人の落とし穴）
- 適用時は所得税分も含め全額が翌年度住民税から控除（振替）
- 申請書の「翌年1月10日」期限は自治体運用で通例だが法令原文は[未確認]（施行規則附則2条の4要照合）

### 制度の動き（2025-2026）

- **2025-10-01〜 ポイント付与禁止** 適用済 [確認済・告示203号]。楽天が国を提訴中
- **2026-10（R8指定期間）〜 指定基準さらに厳格化** [確認済・告示220号]（付加価値基準明確化・調達費用の証明等）。二次情報で「特例控除193万円上限」等の言及あり→ **[未確認・要一次ソース検証]**
- 指定取消が現実に発生（2025年に5団体前後）→ 「寄附先が指定外だと特例分ゼロ」（東京都も対象外 [確認済]）は計算サイトで注意喚起価値あり
- **令和7年税制改正（基礎控除・給与所得控除引き上げ）が上限額計算に直撃** → 大手シミュの更新遅れが起きやすい＝一次ソース準拠の更新体制が差別化になる

## 2. 必要性（やる価値の判定）

### 市場

- 2024年度寄附総額 1兆2,728億円・利用者約1,080万人で過去最高（二次情報）
- 「ふるさと納税 上限 計算」の検索上位は**ポータル大手（楽天・さとふる・ふるなび・チョイス）がほぼ独占**。YMYL領域で個人サイトのビッグワード正面突破は困難
- ただしロングテール（「個人事業主」「正確」「副業」「ワンストップ 確定申告 どっち」等）では個人・中小サイトが実際に食い込んでいる実証あり

### ⚠️ 最重要の競合情報

**keisan-navi.jp（計算ナビ）が本ファミリーとほぼ同型のコンセプト**（国保全国版・都市別計算・保育料・ふるさと納税「精密版」3モードを保有、2026年5月更新確認）。「正確・精密なふるさと納税計算」の単体ポジションは**既に取られている**。後追いは不利。

## 2.5 設計の核：社保側住人と国保側住人で構造が違う（2026-07-25追記）

### 構造差

- **社保側**: 保険料は標準報酬で機械的に決まり、**ふるさと納税をしても社保料は不変**（一方通行の入力）。年収＋県から shahoエンジンで実額自動計算可能 → 大手の「年収×15%概算」との精度差がそのまま差別化
- **国保側**: 所得→国保料→社会保険料控除→課税所得→所得割→上限 の**多段連鎖**。kokuhoエンジン（自治体×所得）で自動化可能。最大の不確実性は保険料でなく**当年所得の未確定**
- **共通の罠（コンテンツ価値大）**: ふるさと納税は**国保料も保育料も下げない**。国保算定は旧ただし書き所得（寄附金控除が入らない）、保育料判定は寄附金税額控除**前**の市町村民税所得割 [実装前に一次ソース照合要・kokuho/hoiku既存知見と整合]。hoiku-keisanを持つ本ファミリーだから正面から書ける注意書き

### 入力データの段階と精度

| 段階 | 取得 | 精度 |
|---|---|---|
| ① 最小 | 年収・家族構成・加入区分 | ±1〜2万円（安全側上限） |
| ② **自動計算（主戦場）** | ①＋県/自治体→**社保/国保料をエンジン実額化**＋国民年金定額 | ±数千円 |
| ③ 実額補完 | ②＋iDeCo・住宅ローン控除（申告分岐）・医療費・副業 | ほぼ確定（生保地震は数百円オーダー） |
| ④ 逆算 | 源泉徴収票 or 住民税決定通知書の所得割額直入力 | 前年ベース確定値 |

**②を無入力に近い操作で出せるのは社保・国保エンジンを持つ側だけ。**

### 「実質の節税額・負荷額」の分解表示（主砲(f)の強化）

- 実質利益 ＝ 返礼品価値（調達3割以下）− 2,000円（ふるさと納税は節税でなく**立替＋返礼品**と明示）
- 負荷額 ＝ 寄付先払い→回収は最長1年半後。**ワンストップ（翌年6月〜住民税減のみ）vs 確定申告（春の所得税還付＋住民税減）で回収の時期と形が違う**のをキャッシュフロー時系列で表示 → 先行者未発見
- 国保側は「所得変動で来年の上限が動く」リスクを併記

### 入力項目の仕分け（2026-07-25追記。判断軸＝影響額÷入力コスト、所得控除Dの上限影響≈D×2〜3%）

**第1フェーズ（MVP・入れるべき）**

- 土台: 年収（or 事業所得）・加入区分・家族構成・県/自治体（社保/国保料は**エンジン自動計算＝入力欄なし**が最大の売り）
- **iDeCo・小規模企業共済**（1欄・影響大: iDeCo満額27.6万→▲約7千円、共済84万→▲約2.1万円。国保側は共済加入率高く必須）
- **青色申告特別控除**（国保側のみ。65/55/10万の選択1つで上限と国保料の両方が動く）
- **分岐スイッチ2つ**: 「医療費控除を申告する?」「寄付先5自治体以内?」→ ワンストップvs確定申告判定(e)が成立
- **住宅ローン控除は あり/なし のみ**（実額不要。「ワンストップなら影響なし/確定申告なら食い合い可能性」の警告分岐として）

**第2フェーズ（入れた方がいい）**

- 医療費控除の実額（30万→▲約8千円・分岐トリガーと兼用で昇格）
- 副業所得（20万超申告層・上限増方向）
- 配偶者の収入額（第1Fは「配偶者あり/なし＋扶養内か」の簡易で可）
- 株式・配当の申告（実装重いが、国保側で「上限は増えるが**国保料も上がる**」損得判定＝kokuhoエンジン保持者だけの第2の主砲。第2F後半〜第3F）

**入れる価値が少ない（省く/詳細設定行き）**

- 生保・地震保険料控除（満額でも▲2千円/▲600円程度→初版は省略＋「±2千円程度の誤差要因」注記）
- 退職金一時金（分離課税で特例分基礎に入らず上限ほぼ不変→入力欄でなく**解説記事**で空白(c)を取る）
- 寡婦・ひとり親・障害者控除（詳細設定行き。hoikuのUI部品流用ならコスト僅少）

**設計思想: 大手詳細版の20項目フォームにしない。「自動計算＋最小入力で±数千円」がターゲット層への正解。**

### keisan-navi.jp との違い＝ターゲット層

keisan-navi は「精密に計算したい給与所得者」向けの汎用精密シミュレータ。本構想は**国保・保育・社保の計算に既に来ている層（自営業・退職前後・子育て世帯）**に、既存エンジンで「あなたの実額」を返す設計。機能の精密さで競うのではなく、**入口（既存1800ページ超の導線）と自動計算資産**で競う。よって「精密版の後発」問題は回避される。

## 3. 実行の仕方（立ち上げ手順案）

前提: 制度ロジックはデータ化／slug不変／個人データ非保持／URLに年度を入れない／暗黙フォールバック禁止／一次ソースのみ——ファミリー共通原則を踏襲。

```
0. 総務省・国税庁の一次ソース再確認（本メモ§4の残検証を潰す）
1. ドメイン検討: furusato-keisan.jp の空き確認（※「ふるさと納税」は商標・指定制度絡みの
   名称リスクなし確認も）。取得したら Cloudflare 追加→SPF/DMARC→shaho と同手順
2. エンジン: shotoku-keisan の課税所得エンジンを再利用（給与所得控除・所得控除・限界税率）
   → 住民税所得割の算出 → 上限逆算式。R8パラメータ（基礎控除等の改正後値）で実装
3. 国保連携: kokuho エンジン注入で「自営業モード」＝自治体選択→国保料自動計算→
   社会保険料控除に自動投入→上限額まで一気通貫（registry正本委譲・slug発明しない）
4. サブ機能: ワンストップvs確定申告判定／育休年モード／指定外自治体（東京都等）警告
5. ページ構成: トップ（給与所得者）＋ /jieigyo/（国保連携・主砲）＋ /onestop/（判定）
   ＋ /ikukyuu/。自治体別ページは作らない（10%全国一律のため薄コンテンツ化する）
6. テスト: 総務省目安表（000816463.pdf）との突合＋shotoku側の検証値と整合
7. 導線: kokuho-keisan（1741ページ）・shaho（47ページ）・shotoku から相互リンク
8. URL監査に追加: 総務省ふるさと納税ポータル・告示一覧・国税庁No.1155
9. 公開時期: 10〜12月の需要期に間に合わせる（逆算すると着手は8-9月が理想）
```
